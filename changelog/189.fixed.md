Invoke tasks now load `.env`, and `backend.load-schemas` derives infrahubctl's `INFRAHUB_ADDRESS`/`INFRAHUB_API_TOKEN` from `INFRAHUB_URL`/`INFRAHUB_TOKEN` when unset. Previously the task failed on a clean shell — even with a correctly populated `.env` — with an error telling the operator to consult `.env.example`, which documented neither variable it asked for. `dev.lab-deploy` gained `--reconfigure`, and `demo.up` uses it when lab nodes already exist, so re-running no longer aborts with "containers already exist".
